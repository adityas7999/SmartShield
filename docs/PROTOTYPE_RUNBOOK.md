# SmartShield v0.1 Prototype Runbook

## What works

The v0.1 prototype runs one real analysis path:

```text
React + Bootstrap workbench
        ↓ POST /api/analyze
FastAPI validation and process orchestration
        ↓ solc --standard-json
Solidity AST JSON
        ↓ analyzer input
C++20 AST adapter + minimal IR facts + TXO-001 rule
        ↓
Finding JSON rendered by React
```

The result is not generated by the frontend or by a source-code regular expression. The backend invokes the official Solidity compiler, and the C++ analyzer interprets its AST.

## Prerequisites

- Node.js 20 or newer and npm;
- Python 3.11 or newer;
- CMake 3.20 or newer;
- a C++20 compiler such as GCC 11+, Clang 14+, or MSVC 2022;
- Git and an internet connection for the initial dependency installation.

The repository pins the official `solc-js` package to **Solidity 0.8.20**. It exposes the same standard JSON compiler interface needed by the analyzer. A native `solc` 0.8.20 executable can be used instead through `SMARTSHIELD_SOLC_BIN`.

## One-time setup

From the repository root:

```bash
# Pin and install the Solidity compiler.
npm ci --prefix backend/solc

# Configure and build the C++ analyzer.
cmake -S core -B build/core -DCMAKE_BUILD_TYPE=Release
cmake --build build/core --parallel

# Create the Python environment and install the API dependencies.
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt

# Install the React application dependencies.
npm ci --prefix frontend
```

On Windows, activate the virtual environment and use its `python`/`uvicorn` executable in place of the Unix-style `.venv/bin/...` paths.

## Run locally

Use two terminals from the repository root.

Terminal 1 — API:

```bash
cd backend
../.venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Terminal 2 — UI:

```bash
npm run dev --prefix frontend
```

Open:

- Workbench: <http://127.0.0.1:5173>
- API documentation: <http://127.0.0.1:8000/docs>
- Health check: <http://127.0.0.1:8000/api/health>

The Vite development server proxies `/api` requests to FastAPI. For a separately hosted frontend, set `VITE_API_BASE_URL` to the API origin before building.

## Verify the vertical slice

In the workbench:

1. Load **Vulnerable sample** and choose **Analyse Contract**. `TxOriginWallet.sol` must produce one `TXO-001` potential finding with high confidence.
2. Load **Safe sample** and analyze it. `MsgSenderWallet.sol` must produce no `TXO-001` finding.
3. Replace the source with invalid Solidity. The UI must show the compiler diagnostic rather than a fake successful result.
4. Use the header control to verify both light and dark modes.

## Run automated tests

```bash
# C++ unit tests: require, assert, if, high/medium confidence, and msg.sender.
ctest --test-dir build/core --output-on-failure

# Real API integration tests using solc and the C++ executable.
.venv/bin/pytest backend/tests -q

# React result, safe-state, and error-state tests.
npm test --prefix frontend

# Production frontend build.
npm run build --prefix frontend
```

## Executable overrides

The defaults are:

- analyzer: `build/core/smartshield-analyzer`;
- compiler: native `solc` on `PATH`, then `backend/solc/node_modules/.bin/solcjs`.

Override either path when needed:

```bash
export SMARTSHIELD_SOLC_BIN=/absolute/path/to/solc
export SMARTSHIELD_ANALYZER_BIN=/absolute/path/to/smartshield-analyzer
```

## v0.1 limitations

- Only `TXO-001` is implemented.
- Only direct `require`, `assert`, and `if` authorization comparisons containing `tx.origin` are inspected.
- Higher confidence currently requires a directly guarded same-function `transfer`, `send`, low-level call, `delegatecall`, or self-destruct effect.
- Modifiers, internal-call propagation, inheritance resolution, proxies, complete CFG/Call Graph construction, and formal exploitability proofs are deferred.
- No finding means only that this detector did not match; it does not mean the contract is secure.
- Reentrancy, ML, automated remediation, persistence, authentication, wallet integration, and blockchain deployment are not part of this prototype.

## Error contract

The API does not return a successful analysis when a required stage fails. Important error codes include:

| HTTP status | Code | Meaning |
|---|---|---|
| 422 | `parse_failed` | `solc` rejected the Solidity syntax |
| 503 | `solc_unavailable` | no configured Solidity compiler is executable |
| 503 | `analyzer_unavailable` | the C++ executable has not been built or configured |
| 502 | `solc_failure` | the compiler process failed unexpectedly |
| 502 | `analyzer_failure` | the C++ analyzer failed and produced no result |
